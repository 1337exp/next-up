## 2. Принципы

1. **Ядро отдельно от интерфейса.** `core/` — чистый TypeScript, ни Vue, ни DOM. Все правила и все тесты на правила живут здесь.
2. **Состояние выводится, а не хранится.** Архив, «дней осталось», теги, группы по месяцам — вычисляются. В данных только то, что ввёл пользователь, плюс минимум служебного.
3. **Любая операция идемпотентна и детерминирована.** Два устройства, выполнившие одно и то же, получают одно и то же (ради слияния и синхронизации).
4. **Все входящие данные проходят через один конвейер версий** (§4): localStorage, файл, сервер.
5. **Адаптивность делает CSS.** Контейнерные запросы TaoUI, а не JS и не пользовательские множители.
6. **Своё пишем, только если в TaoUI/TaoUX нет.** А чего нет — выносим в библиотеку (§11).
7. **Переименование Task → Note** в коде и строках интерфейса: так вы называете сущность.

## 4. Модель данных v2 и версионирование

### 4.1. Модель

```ts
type IsoDate = string;                       // 'YYYY-MM-DD'

interface Note {
  id: string;                                // crypto.randomUUID(); у повтора: `${series}@${due}`
  due: IsoDate;                              // срок (раньше date)
  body: string;                              // Markdown (раньше note)
  items: Item[];
  repeat: Repeat | null;                     // null = не повторяется
  doneAt: number | null;                     // завершена до срока: когда (раньше bool done + updatedAt)
  createdAt: number;
  updatedAt: number;                         // LWW при слиянии
  deletedAt: number | null;                  // надгробие = корзина = безопасное удаление при синхронизации
}

interface Item { id: string; text: string; doneAt: number | null; }   // done = doneAt !== null; один источник правды

interface Repeat {
  series: string;                            // id первой заметки серии
  anchor: IsoDate;                           // опорная дата серии
  every: number;                             // 1..99
  unit: 'day' | 'week' | 'month' | 'year';   // «полгода» = every 6 month
}
```

Исчезает: `rolled` (выводится: следующий повтор есть ⇔ существует запись с id `series@date`), `anchor` как поле заметки (переехал в `repeat`), `done` + `changedAt` (слиты в `doneAt`), перечисление шести вариантов (`every/unit` покрывает их и даёт «каждые 2 недели», «раз в 3 месяца» бесплатно; UI показывает пресеты).

Метки тегов в модель **не** входят: они в тексте, индекс вычисляется (как сейчас, это правильное решение).

### 4.2. Версионирование и миграции (ваша просьба)

Единый конвейер для **любого** входа: `unknown → detect → upgrade → validate → Snapshot v2`.

- `Snapshot = { app: 'nextup', version: 2, exportedAt, notes: Note[] }`. Поле `version` — целое.
- `codec.upgrade(raw)` применяет цепочку чистых функций `v(n) → v(n+1)`; каждая покрыта тестом на замороженном файле-фикстуре. Цепочка сейчас: **legacy** (массив из старого приложения) → **v1** (текущий Next Up, `format: 'nextup'`, `schemaVersion: 1`) → **v2**.
- Результат содержит отчёт: `{ fromVersion, toVersion, upgraded: boolean, invalid, expired }`. Пользователь видит: «Файл версии 1 — обновлён до версии 2, добавлено 31, обновлено 2, пропущено 0».
- Файл **новее** известной версии: не трогаем данные, говорим «файл создан более новой версией, обновите приложение».
- Те же функции стоят на входе из `localStorage` и с сервера: ничего не читается мимо конвейера.
- При первом запуске v3: ключи прежней версии (`nextup-tasks`, `nextup-settings`) читаются **копированием**, не переносом, и остаются нетронутыми как резерв на один релиз.
- Каждый будущий релиз, меняющий схему, добавляет `v2.ts`, поднимает номер и кладёт фикстуру. Ничего больше.

### 4.3. Жизненный цикл (правила, которые переезжают без изменений по смыслу)

«Сегодня» — локальная дата, один таймер до полуночи + пересчёт при возврате на вкладку. Активная: `doneAt === null && due >= today`; всё остальное — архив. Активные — ближайшие сверху, архив — свежие сверху. Разделители по `YYYY-MM`. Срок > 365 дней назад удаляется. Надгробия хранятся 90 дней, чтобы синхронизация успела разнести удаление (§6). Срочность: сегодня / ≤ 7 дней / дальше.

## 5. Повторы: детерминированно

**Решение:** строка на каждый повтор (как сейчас: архив показывает «в этот день было»), но с **детерминированным id** `series@due` и без служебного `rolled`.

- `normalize(notes, today)` для каждой серии создаёт недостающие записи `series@date` от последней существующей до первой будущей. «Недостающая» проверяется по id. Повторный запуск ничего не меняет; два устройства получают **одни и те же** записи.
- Содержимое нового повтора копируется с самой свежей записи серии (текст, пункты без отметок). Править можно любую запись; правка правила (`every/unit`) начинает серию заново: новая `series`.
- Шаг месяца/года считается от `anchor` с прижатием к концу месяца (31 янв → 28 фев → 31 мар) — логика `recurrence.ts` остаётся.
- «Выполнить до срока» повторяющейся записи = `doneAt = now` и создание следующего повтора (как сейчас).
- Шум в архиве: ежедневная серия даёт до 365 записей в год. В данных так и оставляем, а **в интерфейсе подряд идущие архивные записи одной серии сворачиваются** в одну строку «Принять витамины × 90 (12.07 — 10.10)», по клику раскрывается. Это чистая презентация (`lifecycle.groupRuns`), данные не меняются.

Отвергнуто: одна запись серии + виртуальные повторы (как RRULE/iCal). Чище по данным, но «править этот повтор или все?», исключения и история делают интерфейс в разы сложнее; для личного списка оно того не стоит.

## 6. Хранение

- Репозиторий `NotesRepository { load(): LoadResult; save(snapshot): SaveResult }`. Реализация v3 — **localStorage через `createSavedStorage` из TaoUX** (никогда не бросает; повреждённое откладывается в `*.broken`, автосохранение его не затирает). Один ключ `nextup.notes` + `nextup.settings`.
- Запись — после действия, с коротким debounce (≈300 мс), и обязательная запись на `pagehide`/`visibilitychange=hidden`.
- **Несколько вкладок:** событие `storage` (чужая запись) → перечитать, пропустить через `merge` и показать. Сейчас этого нет (в `src` нет ни `storage`-события, ни `BroadcastChannel`), и вторая вкладка перезапишет данные первой при следующей записи.
- IndexedDB — не сейчас: 365 дней × десятки серий укладываются в мегабайты. Интерфейс репозитория позволит заменить хранилище без правки остального. Порог для пересмотра — записи заметно за 3–4 МБ; показатель выводим в настройках.
- «Корзина»: удалённая заметка остаётся надгробием, 30 дней видна в разделе «Корзина» (восстановить / удалить навсегда); сам факт удаления для синхронизации хранится 90 дней. Это бесплатно получается из модели слияния.

## 7. Интерфейс

### 7.1. Структура экранов по ширине (контейнерные запросы, без JS)

| Ширина `AppShell` | Навигация | Список | Редактор |
|---|---|---|---|
| телефон < 600 px | `TaoNav` снизу: Активные · Архив · Теги · Настройки; **«+» — слот `#action`** (круглая кнопка над панелью) | на всю ширину | поверх списка на весь экран |
| планшет 600–840 px | `TaoNav` как рельса слева | колонка | поверх списка, поле шириной ~560 px |
| ПК ≥ 840 px | `TaoNav` как боковая панель с подписями | `TaoSplit`: список (разделитель двигается, ширина запоминается) | **справа в той же панели**, без модальных окон |

Это заменяет режим «Мини», вкладки `TaoTabs` в карточке-тулбаре и `max-width` в `App.vue`.

### 7.2. Размер вместо масштабирования

- На `<html>`: `class="tao-density-auto"` (пальцевые размеры автоматически на `pointer: coarse`) и `tao-size-{small|medium|large}`.
- Настройка одна: «Размер интерфейса» (мал./сред./бол.), по умолчанию — средний. Всё остальное делают масштаб браузера, системный размер шрифта и плотность.
- Никаких своих множителей, переопределённых токенов шрифта и отступов, `--nextup-*-scale`. Удаляются: `FontSizePicker`, `WidthPicker`, поля `uiScale/noteScale/itemScale/headerScale/width` и полтора файла CSS.
- Свайп-панель и прочее измеряют реальные размеры в DOM, а не считают пиксели.

### 7.3. Тема

TaoUI 5: режим `light | dark | auto` (`data-tao-mode`) + одна из 7 палитр (`data-tao-theme`) на `<html>`. Свои цвета бейджей срока (`rgba(110,255,0,.1)`…) заменяются тонами: сегодня — `success`, до 7 дней — `warning`, остальное нейтрально, текст сохраняется («Сегодня», «Дней: 5»). Шумная подложка карточек (`noise-dark.png`) — это `surface="grain"` из коробки. `app.use(TaoUI, { locale })` + `setTaoLocale()` при смене языка: в TaoUI ≥ 4 тексты по умолчанию английские — в текущем приложении это бы всплыло сразу.

### 7.4. Карточка заметки

`TaoCard` с `stripe="left"` и `stripeTone` по срочности. В шапке — тег срока, день недели, дата (копируется по клику, `TaoCopy`), метка повтора, меню «⋮». Тело — `MarkdownView` в `.tao-prose`. Пункты — `TaoChecklist` (`strike`, `counter`, слот `#item` для времени отметки). Действия карточки — **один** список `TaoMenuItem[]` из реестра команд (§8) и для «⋮», и для `TaoContextMenu` (правый клик), и для свайпа на телефоне; на iOS длинное нажатие не вызывает контекстное меню — там «⋮» остаётся. Далёкие задачи (> 21 дня) сворачиваются по настройке — `TaoSpoiler`/`line-clamp` вместо своей логики показа.

Удаление, завершение, снятие отметки — без диалогов: действие выполняется, внизу `toast().action('Отменить', undo)`. Диалог остаётся одним: «Удалить всё».

### 7.5. Поиск, теги

- Поле поиска сверху списка; `/` или `Mod+K` — фокус. Алгоритм прежний (все слова, любой порядок, опечатки, `#тег` — точно), но с **индексом**: нормализованный текст каждой заметки считается один раз на `updatedAt`, а не на каждый символ запроса.
- Переключатель «Точное совпадение» уходит в `TaoPopover` фильтров вместе с будущими фильтрами.
- Раздел «Теги»: вычисляемый список `#тег (N)`; клик = поиск по тегу. На телефоне — пункт навигации, на ПК — под поиском (`TaoTag closable` для выбранных).

### 7.6. Редактор

- Один компонент `NoteEditor`, встроенный (ПК) или экранный (телефон/планшет). **Автосохранение** с коалесценцией правок (400–800 мс), кнопки «Сохранить» нет; «Готово» просто закрывает.
- Поля: срок — `TaoDate` + быстрые чипы «Сегодня / Завтра / +7 / +30», стрелки ±1 день; текст — `TaoTextarea` (автовысота), переключатель «Правка / Просмотр» (`TaoSegmented`) на узких экранах; пункты — список `TaoInput` с добавлением и удалением (удаление слева, как сейчас, чтобы не задевать правым большим пальцем); повтор — пресеты + «Каждые N …».
- Панель Markdown на `TaoToolbar` (жирный, курсив, список, ссылка) — позже (§12, фаза 6): сначала просто textarea.
- Ошибки валидации под полем остаются (`TaoFormField`): пустая заметка, дата старше года.

### 7.7. Настройки (после чистки)

Язык · Тема (режим + палитра) · Размер интерфейса · Сворачивать далёкие задачи · Оповещения о задачах на сегодня · Синхронизация · Данные (экспорт, импорт, корзина, удалить всё) · В режиме разработки — «Демо-данные».
Убрано: ширина «Мини», 4 масштаба, «подтверждать снятие отметки» (заменено отменой).

| поиск по командам (палитра `Mod+K`) | `/palette` (`filterNodes`, `groupByCategory`) — позже |

Не берём: `session` (завязан на камеру и «ноды», см. §11), `History` целиком (снимки всего списка небезопасны при синхронизации, см. §11 и `core/undo.ts`).

## 9. Синхронизация: умнее и проще

Вебхук «заменить целиком» заменяется **синхронизацией документа по HTTP с ETag** — стандартом (RFC 9110), без своих заголовков.

- Протокол: `GET url` → снимок + `ETag` (404 = пусто). `PUT url` с `If-Match: <etag>` (первая запись — `If-None-Match: *`) → новый `ETag`. `412` → клиент делает `GET`, **сливает** (`merge.ts`: по каждому `id` побеждает больший `updatedAt`; надгробие побеждает более старую живую запись), снова `PUT` (до 3 попыток). Диалогов нет.
- Те же две операции умеют **WebDAV/Nextcloud, S3 (предподписанный URL) и любой статический файл-сервер с ETag**, поэтому отдельного сервера может не понадобиться. Токен — в URL (как сейчас) либо в поле «Authorization».
- Запуск: через 3 с после правки (debounce), при старте, при возврате на вкладку, при `online`, кнопка «Синхронизировать». Состояние (`idle · syncing · offline · error`) — строка в настройках и маленький индикатор в навигации.
- Интерфейс провайдера `SyncProvider { pull(); push(snapshot, etag) }` — другие бэкенды добавляются отдельно (например, File System Access API на ПК; на телефоне он недоступен, поэтому не основа).
- Демо-сервер `examples/server` сокращается до ~40 строк (файл + хеш как ETag).
- Позже, по желанию: сквозное шифрование снимка перед отправкой (WebCrypto AES-GCM, пароль-фраза; в старом коде был `std/crypto.ts`). Закрытый сайт и оповещения «при закрытом приложении» всё равно требуют push-сервера: оставляем в backlog, как и раньше.

## 11. Чего не хватает и что заметил в TaoUI/TaoUX

> **Статус на 29.10.2026: все пункты ниже закрыты в библиотеках** (TaoUI 5.6.0, TaoUX 0.3.0 и модуль `undo`, ветка `undo` в TaoUX). В приложении уже используются: иконки `tao-*`, `uuid()`, `storage.subscribe` / `tryWrite`, `TaoDate editable`, нижний лист и полноэкранная модалка, `SwipeTracker` + `settleOpen`, `undo`. Пункты оставлены как история решений.

Багов в строгом смысле при чтении не нашёл, но **я не запускал библиотеки**: проверю по ходу работы и сообщу отдельно. Ниже — несоответствия и пробелы, из-за которых я пишу своё. Пометка: **P1** — упираемся прямо в фазах 1–3, **P2** — желательно.

**TaoUX**

- **P1 `session`** требует `camera`, `countNodes`, ключи вида `loadedWithDropped` («связей отброшено»): это сессия графа. Для любого другого документа (список заметок) непригодна. Предложение: сделать камеру необязательной и переименовать `countNodes` → `countItems`.
- **P1 `ids`**: `uid(prefix)` — счётчик в модуле, с нуля при каждой загрузке. Годится для узлов в сессии, но не для постоянных и синхронизируемых записей. Нужен `uuid()`/`randomId()` (на `crypto.randomUUID` с запасным вариантом).
- **P1 `storage`**: нет `remove`, нет подписки на событие `storage` (несколько вкладок), `write` не отличает «квота» от «запрещено». Предложение: `subscribe(cb)` и причина отказа.
- **P2 `file`**: `downloadText` зашит в `application/json` (имя говорит «text»); нет парной функции чтения выбранного файла с проверкой `MAX_FILE_BYTES` (константа есть, читателя нет). Предложение: параметр `mime` и `readTextFile(file, limit)`.
- **P2 `History`**: снимки — полные строки всего документа. Каждый снимок — весь список (сотни КБ при сотнях записей), а хранится до 100 штук; и отмена, сделанная после прихода синхронизации, откатит чужие изменения. Для документов вроде списка заметок нужен вариант «обратных операций» (снимки «до» только затронутых записей). Пока пишу `core/undo.ts` (~40 строк), потом можно вынести в TaoUX.
- **P2 жест «свайп»** (`gestures`: tap/double/long-press/pinch есть, свайпа нет). У меня есть `lib/swipe.ts` — чистое распознавание намерения (горизонталь/вертикаль/дрожание) и `settleOpen`: естественно переезжает в TaoUX `gestures` как `SwipeTracker`, с тестами.

**TaoUI**

- **P1 иконки**: из 29 встроенных нет прикладных — настройки, правка, корзина, повтор, колокольчик, тег, отмена. Регистрирую 8 своих через `registerTaoIcons`; если решите расширить набор, они уйдут в библиотеку.
- **P1 `TaoDrawer`/`TaoModal` на телефоне**: у Drawer только `side: left|right`, у Modal нет полноэкранного варианта. Нужен `side="bottom"` (нижний лист) и `fullscreen` на узких экранах — главный жест телефонного интерфейса.
- **P1 `TaoDate`**: только выбор из календаря. Нет ввода с клавиатуры (`5`, `5.3`, `05.03.26`) и формата `dd.mm.yyyy` в поле. Быстрый ввод даты — функция старого приложения, которая ценна на ПК. Предложение: режим `editable` с `parse`/`format`.
- **P2** помощник анимации списка по высоте для `TransitionGroup` (убирает `lib/collapse.ts`, 77 строк); строка-свайп с действиями (`TaoSwipeRow`, если жест уйдёт в TaoUX); сортируемый список (перестановка пунктов, ручка `tao-grip` уже есть, а поведения нет).
- Проверить при интеграции: `TaoDate`/`TaoCalendar` берут язык из `setTaoLocale` (по коду так: `props.locale ?? appLocale.code`, документация говорит `en-US` по умолчанию) и `TaoCopy`/прочие тексты не остаются английскими.

Рабочий процесс: в фазе 0 подключаю библиотеки через `file:../taoui`, `file:../taoux` (в `vite.config.ts` — `resolve.dedupe: ['vue']`, в `tsconfig` — `paths` на `node_modules/vue`, как описано в README TaoUX). Патчи вносим сразу в библиотеки, в конце фазы публикуем и возвращаемся на semver.

## 15. Решения, которые нужны от вас

В каждом пункте есть рекомендация, по умолчанию иду по ней.

1. **Повторы:** строка на каждый повтор с детерминированным id (**рекомендую**) — или одна запись с виртуальными повторами (§5).
2. **Чек-лист:** отдельные пункты с метками времени (**рекомендую**, как у вас) — или стандартные пункты Markdown `- [ ]` прямо в тексте. Второй вариант проще и переносимее, но теряет время отметки и удобство ввода на телефоне.
3. **Экран выбора языка:** убрать, определять по `navigator.languages` и менять в настройках (**рекомендую**) — или оставить как в v1.
4. **Редактор:** встроенный с автосохранением, на телефоне экранный (**рекомендую**) — или модалка с «Сохранить».
5. **Размер интерфейса:** оставить одну настройку мал./сред./бол. (**рекомендую**) — или убрать совсем и положиться на масштаб браузера.
6. **Library-first:** патчить TaoUI/TaoUX по ходу (**рекомендую**) — или копить список и править в конце.
