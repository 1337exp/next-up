### 2.2. Что исправляем при переносе

Это находки при чтении кода, а не «кривизна»: часть из них годами не проявлялась.

1. **Дата строкой `dd.mm.yyyy`** парсится при каждом сравнении и сортировке. Храним ISO `YYYY-MM-DD` (тот же формат у `TaoDate`); `dd.mm.yyyy` остаётся только в поле ввода.
2. **Вычисляемые поля в данных.** `daysCountdown` и `changedMonth` записываются прямо в задачи и уходят в `localStorage`. Считаем их в селекторах, храним только данные.
3. **Разница в днях и летнее время.** `getDaysDifference` делает `Math.floor(мс / 86 400 000)` по локальной полуночи. В сутки с переходом на летнее время (23 часа) это даёт 0 вместо 1 (проверил в `Europe/Berlin`). Считаем через `Date.UTC`.
4. **«Каждый месяц» через `setMonth(+1)`:** 31 января + 1 месяц = 3 марта (проверил). Прижимаем к последнему дню месяца и считаем от опорной даты серии (`anchor`, §5), чтобы 31-е не «съезжало» на 28-е.
5. **Магические числа.** `rollOver` = 0/1/2/3/30/4 → строковый union; `irrelevant` → `done`; `markProc` (0/1) → `rolled: boolean`.
6. **`updateAndSaveTasks`** (~150 строк, с рекурсией) смешивает сортировку, архив, повторы, чистку, группировку и сохранение. Разбиваем на чистые функции в `domain/` с тестами.
7. **Разделитель месяцев** сравнивает только номер месяца: январь 2026 и январь 2027 подряд не разделятся. Ключ группировки — `YYYY-MM`.
8. **`lastChange` чек-листа** хранится как `Date.toString()` (таймзона и локаль внутри строки). Храним ISO-время, форматируем при показе.
9. **Импорт JSON** добавляет элементы без проверки формата и без защиты от дублей по `id`. Нужны валидация и слияние по `id`.
10. **Таймер раз в секунду** ради смены даты. Достаточно одного таймера до полуночи и пересчёта по `visibilitychange`.
11. **`@daeren/i18n`:** `te()` после первого вызова всегда возвращает `true` (проверяется `Map.has`, а не сохранённое значение); пакет отдаёт сырой `index.ts` через `exports`.

## 5. Доменная модель

```ts

interface ChecklistItem {
  text: string;
  done: boolean;
  changedAt: string | null;   // ISO-время последней отметки, null — не отмечен
}

interface Task {
  id: string;                 // crypto.randomUUID()
  date: string;               // 'YYYY-MM-DD' — календарный день, без времени и пояса
  note: string;               // Markdown
  checklist: ChecklistItem[];
  recurrence: Recurrence;

  done: boolean;              // было irrelevant: закрыта до срока
  rolled: boolean;            // было markProc: следующий повтор уже создан
  updatedAt: number;          // мс; понадобится для слияния при синхронизации
}

interface Settings {
  schemaVersion: 1;
  locale: 'ru' | 'en' | null; // null — язык ещё не выбран
  width: 'auto' | 'mini';     // «Авто» — на всю ширину окна, «Мини» — не шире 400 px по центру
```

**Не хранится, считается:** `daysLeft = diffDays(today, task.date)`, `isArchived = task.done || daysLeft < 0`, группа месяца.

**Соответствие старому формату (для импорта):**

| Старое | Новое |
|---|---|
| `date: 'dd.mm.yyyy'` | `date: 'YYYY-MM-DD'` |
| `rollOver` 0 / 1 / 2 / 3 / 30 / 4 | `none` / `daily` / `weekly` / `monthly` / `semiannual` / `yearly` |
| `irrelevant` | `done` |
| `markProc !== 0` | `rolled: true` |

## 6. Жизненный цикл задач (правила из старого кода)

Это спецификация поведения, которое нужно сохранить; на неё же пишутся тесты.

1. **«Сегодня»** — локальная календарная дата. Хранится реактивно в `useToday()`: один таймер до ближайшей полуночи + пересчёт при возврате на вкладку.
2. **Активная** задача: `!done && date >= today`. Всё остальное — архив. Задача на сегодня — ещё активная.
3. **Сортировка:** активные по дате по возрастанию (ближайшие сверху), архив по дате по убыванию (свежие сверху).
4. **Разделитель** при смене `YYYY-MM`: «К{квартал} / {Месяц}», отдельно в каждом из списков.
5. **Бейдж срока:** сегодня — зелёный, ≤ 7 дней — красный, дальше — нейтральный; подпись «Сегодня» или «Дней: N».
6. **Повторы и догон.** Для задачи с `recurrence !== 'none'` повторы — детерминированная функция от `anchor` и правила: повтор номер `n` = `anchor + n · период`. Месяцы и год считаются от `anchor`, а не от предыдущей копии, с прижатием к последнему дню месяца: 31 января → 28 февраля → 31 марта → 30 апреля, без «дрейфа» на 28-е.
   Когда задача уходит в архив (прошла дата или нажали «выполнено») и у неё `!rolled`:
   - у исходной ставится `rolled = true`;
   - создаётся запись на каждый следующий повтор, пока его дата не дойдёт до сегодняшней или будущей: новый `id`, чек-лист сброшен, `done = false`;
   - пропущенные повторы создаются сразу как архивные, с `rolled = true`: по одной записи на каждый пропущенный раз, поэтому по архиву видно, что задача была в день X;
   - первый непропущенный повтор — обычная активная задача;
   - «выполнено» до срока запускает следующий повтор ровно один раз;
   - повторный запуск ничего не создаёт: у всех исходных уже `rolled = true`.
   Шаг симуляции — повтор, а не календарный день. Результат тот же, что у прогона по дням (это проверяет тест в §13), потому что следующий повтор зависит только от правила и даты, а за время отсутствия ни одна задача не могла измениться.
7. **Чистка:** задачи старше 365 дней удаляются. Повторы старше 365 дней при догоне не создаются вовсе: чистка всё равно удалила бы их. Создать или изменить задачу на дату старше 365 дней назад нельзя.
8. **Когда пересчитывать:** при старте, при смене дня и после любого изменения — одно действие стора `normalize()`. Отметка пункта чек-листа сохраняется без пересчёта.
9. **Клонирование:** копируются дата, заметка и чек-лист с сброшенными отметками; повтор не копируется. Сохранение создаёт новую задачу.
10. **Форма:** дата обязательна; нужна хотя бы заметка или один пункт чек-листа.
11. **Удаление** и «удалить всё» — через `confirm()`.

## 7. i18n в чистом Vue

В Nuxt-плагине вся магия — реактивный `curLocale`, чтобы `t()` перерисовывал шаблоны. В чистом Vue это тот же `ref` на уровне модуля: плагин не нужен, достаточно композабла.

**Решение:** свой модуль вместо `@daeren/i18n` и вместо `vue-i18n`.

- Формат и API переносятся без изменений: пути с точками, `{0}`, `t(path, args)`. Старые строки остаются как есть.
- `vue-i18n` для двух языков избыточен.
- Если захочется оставить `@daeren/i18n`, меняется только функция `translate` ниже: `ref` и композабл те же.

**Типобезопасность.** `ru.ts` — источник правды, `en.ts` обязан повторять его ключи, а в `t()` допустимы только существующие пути. Опечатка в ключе и пропущенный перевод ловятся компилятором (проверил на черновике: `tsc` падает на отсутствующем ключе).

```ts
// i18n/locales/ru.ts
export default {
  ui: { button: { save: 'Сохранить', cancel: 'Отмена' } },
  tasks: { today: 'Сегодня', daysLeft: 'Дней: {0}' },
} as const;

// i18n/locales/en.ts
import type ru from './ru';
type DeepStrings<T> = { [K in keyof T]: T[K] extends string ? string : DeepStrings<T[K]> };

export default {
  ui: { button: { save: 'Save', cancel: 'Cancel' } },
  tasks: { today: 'Today', daysLeft: 'Days: {0}' },
} satisfies DeepStrings<typeof ru>;
```

```ts
// i18n/core.ts
import { computed, ref } from 'vue';
import ru from './locales/ru';
import en from './locales/en';

export const LOCALES = { ru, en } as const;
export type LocaleCode = keyof typeof LOCALES;
export const LOCALE_CODES = Object.keys(LOCALES) as LocaleCode[];

type Paths<T, P extends string = ''> = {
  [K in keyof T & string]: T[K] extends string ? `${P}${K}` : Paths<T[K], `${P}${K}.`>;
}[keyof T & string];
export type MessageKey = Paths<typeof ru>;

const current = ref<LocaleCode>('ru');

export function setLocale(code: LocaleCode) {
  current.value = code;
  document.documentElement.lang = code;
}

function lookup(dict: unknown, path: string): string | undefined {
  let cur: any = dict;
  for (const part of path.split('.')) {
    if (cur == null || typeof cur !== 'object') return undefined;
    cur = cur[part];
  }
  return typeof cur === 'string' ? cur : undefined;
}

export function translate(code: LocaleCode, key: MessageKey, args: readonly (string | number)[] = []) {
  const tpl = lookup(LOCALES[code], key) ?? lookup(LOCALES.en, key) ?? key; // fallback: en → сам ключ
  return tpl.replace(/\{(\d+)\}/g, (m, i) => (i in args ? String(args[+i]) : m));
}

export function useI18n() {
  return {
    locale: computed(() => current.value),
    // читает current.value внутри, поэтому шаблоны перерисовываются при смене языка
    t: (key: MessageKey, args?: readonly (string | number)[]) => translate(current.value, key, args),
    setLocale,
  };
}
```

**Что перенесено из старых `locales/*.js`.** Файлы по ~520 строк, в основном под облако и другие страницы. Взяты строки, которые реально использовал `Track/*` (ключи нашёл поиском по коду), с новыми путями: `page.track.*` → `tasks.*` и `settings.*`, `ui.popconfirm.*` → `ui.confirm.*`, `rollOver.mode.*` → `tasks.form.repeat.*` (имена совпадают с `Recurrence`). Тексты не менялись; добавлены `language.*` и `settings.title`. `format.ts` содержит пока только `monthName`; остальное (квартал, день недели) добавится на этапе 3 вместе с датами.

**Даты и названия.** Таблицы месяцев и дней из `std/time.ts` заменяем на `Intl.DateTimeFormat(locale, …)`. Проверил: для `ru` `month: 'long'` даёт «январь», `weekday: 'short'` даёт «чт» (строчными), поэтому первую букву поднимаем сами. Префикс квартала («К» / «Q») — обычный ключ в словаре.

**Множественные числа** пока не нужны (в старых строках «Дней: {0}»). Если понадобятся: `Intl.PluralRules`.

## 8. Первый запуск и язык в настройках

1. **Старт.** `main.ts` читает настройки. Если `settings.locale` валиден — `setLocale()` до первого рендера, чтобы не было мигания. Иначе `App.vue` показывает `LanguageGate`.
2. **`LanguageGate`:** два крупных варианта «Русский» / «English». Предложенный язык выделен и в фокусе: берётся первый поддерживаемый из `navigator.languages`, иначе английский. Предложение само не сохраняется, пока пользователь не выберет язык. Клик (или Enter) сохраняет выбор и открывает приложение. Сам экран сразу переключается на выбранный язык.
3. **Настройки.** `LanguagePicker` (`TaoSegmented`) — тот же компонент, что в гейте. Меняет язык сразу, без перезагрузки, обновляет `<html lang>`.
4. **Повреждённые данные.** Значение вне `LOCALE_CODES` считается «не выбран».

## 9. Хранение, миграции, импорт и экспорт

- **Ключи:** `nextup-settings` и `nextup-tasks`, у каждого `schemaVersion`. Префикс отличается от старого `md.tools.track.*`, чтобы не пересечься.
- **Запись:** явно в конце каждого действия стора (один `commit()`), как и раньше, без deep-watch.
- **Ошибки:** сам доступ к `window.localStorage` может бросить исключение (iframe с `sandbox`, запрет cookies, WebView без DOM storage), поэтому доступ проверяется пробной записью; при отказе (и при квоте) приложение работает в памяти, ничего не бросая. Стор отдаёт флаг `persistent`; предупреждение пользователю (`toast().error()`) добавим вместе со списком на этапе 3.
- **Миграции:** `migrate(raw)` по `schemaVersion`, на каждую версию тест.
- **Общий формат обмена** (для файла и для будущей синхронизации):

```ts
interface Snapshot {
  format: 'nextup';
  schemaVersion: 1;
  exportedAt: number;
  tasks: Task[];
}
```

- **Экспорт:** файл `nextup-YYYY-MM-DD.json`.
- **Импорт** (`TaoFileDrop`): определить формат (новый `Snapshot` или старый массив `ITask[]`) → привести к новой схеме → проверить каждую запись → слить по `id` (при совпадении побеждает больший `updatedAt`) → показать итог «добавлено N, обновлено M, пропущено K».
- **Основной путь переноса данных из старого приложения:** экспорт в старом → импорт в новом.

## 10. Точки расширения для синхронизации

Синхронизация — это экспорт и импорт по сети, поэтому отдельного формата не нужно: «выход» = `exportSnapshot()`, «вход» = `importSnapshot()`. Оба нужны уже в v1 для файлового экспорта.

```ts
// sync/types.ts
interface SyncAdapter {
  pull(): Promise<Snapshot>;                // вход: получить внешнее состояние
  push(snapshot: Snapshot): Promise<void>;  // выход: отдать текущее
}
type MergeStrategy = 'replace' | 'merge-by-updated-at';
interface ImportReport { added: number; updated: number; skipped: number; invalid: number }

// stores/tasks.ts
exportSnapshot(): Snapshot
importSnapshot(s: Snapshot, strategy: MergeStrategy): ImportReport
```

**Закладываем в v1**

- `settings.sync.endpoint` в модели настроек (пустая строка = выключено).
- `Task.updatedAt` и `Snapshot.schemaVersion`.
- `exportSnapshot` / `importSnapshot` / интерфейс `SyncAdapter`.
- `sync/index.ts`: `getSyncAdapter(settings): SyncAdapter | null`, в v1 всегда `null`.
- Два хука в сторе: `onStart` (потенциальный pull) и `onLocalChange` после `commit()` (потенциальный push с debounce). В v1 пустые.
- Поле endpoint в UI спрятано за константой `FEATURES.sync = false`, чтобы в интерфейсе не было поля, которое ничего не делает.

**Сделано (грубая схема «целиком»).** Вместо `GET`/`PUT` с `ETag` взят вебхук с токеном в адресе и метками времени: клиент хранит `changedAt` (последняя правка на устройстве) и `syncedAt` (`exportedAt` последней синхронизации). «Скачать» предупреждает, если `changedAt` позже снимка на сервере; «Загрузить» отправляет `syncedAt` заголовком `X-Nextup-Synced-At`, а сервер отвечает `409`, если у него данные новее. Код: `sync/webhook.ts`, `stores/sync.ts`, `composables/cloudSync.ts`, `components/SyncSection.vue`; протокол и демо-сервер: `examples/`. Учёт **по отдельным записям** (слияние по `updatedAt`, надгробия, `ETag`) остаётся на потом: формат снимка для него уже подходит.

**Откладываем осознанно**

- Удаления (tombstones): без них слияние «воскрешает» удалённые задачи. Решаем вместе с реальным протоколом.
- Протокол endpoint. Самый простой вариант: `GET` / `PUT` одного JSON-документа `Snapshot`.
- Авторизация и шифрование перед отправкой (в старой версии было, `std/crypto.ts`).

**Безопасность на будущее:** endpoint задаёт пользователь, поэтому только `https://` (и `http://localhost`), таймаут, никаких отправок без явного включения. Токен в `localStorage` доступен любому XSS, поэтому заметки рендерятся без raw HTML (§3).

  - Ежедневная задача за год даёт до 365 архивных записей (по записи на каждый пропущенный день, как и договаривались); если архив станет шумным, это решается сворачиванием серий.
  - В WebView Android скачивание Blob-ссылкой и выбор файла работают только при поддержке со стороны приложения-хозяина (обработчик загрузок и `onShowFileChooser`); в браузере проверено тестами с подменой, на устройстве нет.

## 13. Тесты (Vitest)

- **date:** `parseUserDate` (`5`, `5.3`, `05.03.2026`, мусор → `null`, месяц 13 → `null`); `diffDays` через границу летнего времени (`TZ=Europe/Berlin`); `addMonthsClamped` (31 января → 28 / 29 февраля).
- **lifecycle:** граница активная / архив (`date === today` — активная); сортировка; группировка по `YYYY-MM` с переходом через год.
- **recurrence, эквивалентность:** догон одним `normalize(today)` даёт то же множество записей, что пошаговый прогон `normalize(d)` по каждому дню от последнего запуска до `today` (случайные наборы задач и сроки пропуска).
- **recurrence:** `monthly` от 31 января даёт 28.02, 31.03, 30.04 (без дрейфа); `daily` с пропуском 30 дней; `weekly`, `monthly`, `semiannual`, `yearly`; «выполнено до срока» создаёт следующий повтор ровно один раз; повторный `normalize()` ничего не добавляет; чек-лист сбрасывается.
- **Чистка:** задачи старше 365 дней удаляются после генерации повторов.
- **migrations:** старый формат → новый (маппинг полей, `lastChange` → ISO), невалидные записи пропускаются и считаются.
- **snapshot:** слияние по `id` и `updatedAt`, `updatedAt: 0` у импортированных старых записей.
- **i18n:** оба словаря с одинаковыми ключами (проверка на уровне типов) и fallback на `en`.

## 14. Решения и открытые вопросы

**Решено**

1. **Иконки:** fontello из `src/assets/fontello`.
2. **i18n:** свой модуль, без зависимости (§7).
3. **Догон повторов:** остаётся, по записи на каждый пропущенный повтор (§6, п. 6).
4. **Повторы:** этап 5, привязки ко времени нет.
5. **Деплой:** статический SPA, встраивается куда угодно; `localStorage` привязан к origin, данные переносятся экспортом / импортом.
6. **Roboto:** локальный; `roboto.css` обновляет автор проекта.
7. **Префикс хранилища:** `nextup-*`, защита от коллизий при разных способах встраивания.

**Открыто**

1. **Способ встраивания** (`iframe` или модуль в страницу хоста) решать не нужно, пока не дойдём до деплоя: префикс `nextup-` покрывает оба случая. Для android-WebView понадобится включённый DOM storage; запускать лучше через `WebViewAssetLoader`, а не `file://` (рекомендация, на устройстве не проверял).
