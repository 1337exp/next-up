# Примеры

## Демо-сервер синхронизации (`server/`)

Один файл на Node (18+), без зависимостей. Хранит по одному JSON-документу на токен и умеет ровно то, что нужно приложению: отдать и принять документ с проверкой `ETag`. Это пример для знакомства с протоколом, а не готовый сервис: нет шифрования, учёта пользователей и защиты от перебора токенов.

```bash
npm run example:server              # http://localhost:8787
PORT=9000 DATA_DIR=./data node examples/server/server.mjs
```

В приложении: **Настройки → Синхронизация**, адрес документа `http://localhost:8787/mysecret123` (токен — часть адреса, от 8 до 64 символов: буквы, цифры, `_`, `-`), включить переключатель. На втором устройстве тот же адрес. Данные лежат в `examples/server/data/<токен>.json` (папка в `.gitignore`).

Как это работает для пользователя: правка уходит на сервер через 3 секунды, при возврате на вкладку и при появлении сети приложение забирает чужие правки. Диалогов «заменить?» нет: если два устройства правили одновременно, слияние по записям разбирает всё само (побеждает более поздняя правка записи, удаление не воскресает).

## Протокол

Один адрес, одно JSON-тело (снимок: `{ "app": "nextup", "version": 2, "exportedAt": <мс>, "notes": [...] }`, тот же формат, что у файла экспорта). Это обычные условные запросы HTTP ([RFC 9110](https://www.rfc-editor.org/rfc/rfc9110#name-conditional-requests)), поэтому то же самое умеют **WebDAV (Nextcloud)**, S3 по предподписанной ссылке и любой файловый сервер с ETag: отдельный сервер может не понадобиться.

| Запрос | Ответ |
| --- | --- |
| `GET` | `200` документ и заголовок `ETag` · `404` на сервере пока ничего нет |
| `PUT` с `If-Match: <ETag>` | `200` записано, новый `ETag` · `412` документ изменился после чтения |
| `PUT` с `If-None-Match: *` | `201` создан · `412` документ уже есть |
| `OPTIONS` | `204` и заголовки CORS |

Алгоритм клиента (`src/core/sync.ts`):

1. `GET` → документ и `ETag`.
2. Слить с локальными записями по `id` (побеждает больший `updatedAt`; при равенстве побеждает удаление) и принять результат.
3. Если у клиента есть то, чего на сервере нет в таком же виде, `PUT` с `If-Match` (или `If-None-Match: *` для первого документа).
4. `412` — кто-то записал между шагами 1 и 3: вернуться к шагу 1, не более трёх кругов.

Версии формата: документ любой известной версии (и файл самого первого приложения) поднимается до текущей при чтении; документ более новой версии клиент не трогает и сообщает об этом.

### Для своего сервера

- Сервер должен отдавать `ETag` и принимать `If-Match` / `If-None-Match` в `PUT`.
- Страница ходит с другого origin, поэтому нужен CORS: `Access-Control-Allow-Headers: Content-Type, If-Match, If-None-Match, Authorization` и **`Access-Control-Expose-Headers: ETag`**. Без последнего браузер не покажет странице `ETag`, и клиент запишет документ безусловно (слияние всё равно будет, но гонка двух одновременных записей не отловится).
- Авторизация: токен в адресе либо готовое значение заголовка `Authorization` (`Bearer …`, `Basic …`) в настройках.
- Адрес только `https://` (или `http://localhost` для пробы); логин и пароль в самом адресе не принимаются.
- Размер документа не больше 5 МБ.
